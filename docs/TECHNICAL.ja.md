# 実装メモ

DekaDesktopIcon は Explorer 自身のデスクトップ ListView に DLL を読み込み、描画サイズを拡張します。実行ファイルの機械語やディスク上の Windows ファイルは変更しません。

## ソース構成

| ファイル | 責務 |
| --- | --- |
| `src/DekaDesktopIcon.cpp` | GUI、引数処理、画像設定、JSON 出力 |
| `src/CommandClient.cpp` | 対象検証、排他、DLL フック、IPC、保存済み配置の復旧 |
| `src/Protocol.h` | コマンド、共有メモリ形式、メッセージ識別子 |
| `src/Win32Support.h` | パス、設定ファイル、共通 Win32 ヘルパー |
| `src/ShellDesktop.h` | デスクトップ検出、IFolderView2、項目の識別、配置バックアップ |
| `src/DekaDesktopIconCore.cpp` | 状態管理、ListView サブクラス、描画、同期、復元 |
| `src/Imaging.h` | WIC 読み込み、Shell 画像取得、GDI+ 変換 |
| `src/Interaction.h` | 選択、範囲選択、内部移動、プレビュー、Shell ドラッグへの委譲 |
| `src/DropTarget.h` | ドロップ先の座標変換、Shell のドロップ処理と画像の連携、登録の復元 |
| `src/ContextMenu.h` | Explorer 標準メニューへの委譲、非同期表示の観測 |
| `tests/RegressionChecks.h` | コア内で実行する操作・整列・メニューの開発用検証 |
| `tests/DragDropChecks.h` | ドロップ先の描画・座標・操作説明・委譲の回帰検証 |
| `tests/DragFeedbackHost.h` | 実際のマウス入力と Shell 画像を使う、ファイル操作を実行しないプレビュー |
| `tests/DekaDesktopIconTestHost.cpp` | 独立したネイティブ ListView による試験 |
| `tests/DekaDesktopIconSortTest.cpp` | 実際の Explorer の並べ替えコマンドの試験 |

コア内部のヘッダーは同じ匿名名前空間で状態・座標変換を共有します。検証コードを別ファイルに分けていますが、実際の入力経路を検証するためコアにコンパイルします。

## 適用と通信

コントローラーは対象のプロセスパス、ログインセッション、ネイティブウィンドウ構造を検証します。対象 UI スレッドに一時的な `WH_GETMESSAGE` フックを設定して DLL を読み込みます。登録メッセージを PostMessage で送り、処理の完了を待ってフックを解除します。Shell の COM 処理は入力同期 SendMessage の中では実行しません。

共有メモリは `Local\DekaDesktopIcon-v3-<pid>`、プロトコルはバージョン 3 です。コントローラー間は名前付き mutex で直列化します。アクティブな DLL のフルパスを照合し、別フォルダーのコピーで上書きしません。改名前の v2 マッピングも読み取り専用で調べ、有効な旧パッチの上にサブクラスを重ねることを防ぎます。

ListView と親の `SHELLDLL_DefView` のサブクラス、および関連状態の変更はデスクトップ UI スレッドで実行します。画像読み込みはワーカーで行い、世代番号で古い結果を破棄します。公開された画像は mutex の下で参照を共有します。

## 描画と同期

専用画像リストに指定サイズを設定し、`NM_CUSTOMDRAW` で画像・ラベル・選択表示を描きます。手動の画像割り当てを WIC で優先して読み込み、割り当てがない項目は `IShellItemImageFactory::GetImage` に最大描画サイズの 1024 px を要求します。`SIIGBF_RESIZETOFIT | SIIGBF_BIGGERSIZEOK` により Shell のサムネイルを優先し、サムネイルがない項目は標準アイコンを取得します。取得した画像は縦横比を保って中央に拡大表示します。

Explorer が並べ替え等で画像リストを交換・縮小した場合は、最新の標準リストを復元対象として保持し、専用リストを再設定します。項目順・識別子・配置を同期し、元の配置のバックアップや試用期限を更新しません。項目の一致判定にはインデックスではなく Shell の解析名を使います。

表示上のアイコン矩形と標準 ListView の内部矩形は一致しない場合があります。矩形取得・ヒットテスト・選択・範囲選択・ドラッグを同じビュー座標で処理し、描画時にクライアント座標へ変換します。プレビューは透過画像と掴んだ位置を保持します。内部移動は Shell の項目位置 API に反映し、外部へのドラッグは標準経路へ委譲します。

Explorer のドロップ先は内部の小さい矩形を直接参照するため、ListView のヒットテストメッセージの差し替えだけでは拡大表示に対応できません。ListView に `IDropTarget` の中継を登録し、表示上のアイコン・ラベルへの重なりを同じ項目の内部矩形へ変換して、既存 Shell ビューの `DragEnter` / `DragOver` / `Drop` に渡します。小さい表示サイズで内部ラベルだけが空白へはみ出す場合も背景へ補正します。`IDropTargetHelper` に実際の画面座標を渡し、ドラッグ画像と説明文は実際のポインターに追従させます。`LVIS_DROPHILITED` / `CDIS_DROPHILITED` を独自描画へ反映し、元の選択は維持します。

ハイライトは固定の半透明色ではなく、対象 ListView に対する `OpenThemeData` / `DrawThemeBackground` で描画します。デスクトップ独自のテーマ設定を尊重し、テーマが無効な場合はシステムの選択色へフォールバックします。

このビューからのドラッグ中は、開始時に記録した全項目の解析名でドラッグ元を照合し、項目へのドロップ先から除外します。元の項目上では Shell に背景の座標を渡し、`DragEnter` / `DragOver` / `Drop` を通じて自己フォルダーへの移動や強調表示を防ぎます。現在の選択状態やインデックスに依存せず、外部からのドラッグでは選択中の項目も通常どおり宛先になります。

内部のアイコンやラベルが隣の項目と重なる場合があるため、変換先は矩形の中心だけで決めず、標準ヒットテストで目的の項目に命中する座標を確認します。背景の座標が表示領域内に見つからない場合も、項目に命中しない領域へ退避させます。

Shell ドラッグへの切り替え時には、既存ビューの選択から `IDataObject` を取得し、`IDragSourceHelper2::SetFlags(DSH_ALLOWDROPDESCRIPTIONTEXT)` を画像初期化より先に呼び出して、`SHDoDragDrop` を実行します。[Windows の仕様](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl/nf-shobjidl-idragsourcehelper2-setflags)では、独自画像を渡すだけでは操作説明が無効になるためです。説明文と効果は Shell が提供します。空白やドラッグ元の項目へ戻って左ボタンを離した場合は既存の配置処理に引き継ぎ、グリッドや掴んだ位置を維持します。

独自画像の初期化で `IsShowingText` が無効になる場合があるため、初期化後に明示的に有効化します。これは [Windows Forms の実装](https://source.dot.net/System.Private.Windows.Core/System/Private/Windows/Ole/DragDropHelper.cs.html)でも使用される補正です。説明データの更新だけでは表示が更新されないため、`DragWindow` 形式の DWORD ハンドルを読み取り、[DDWM_UPDATEWINDOW](https://learn.microsoft.com/en-us/windows/win32/shell/ddwm-updatewindow) を通知します。`DragEnter` / `DragOver` と送信側の `GiveFeedback` の両方から更新します。

Shell のドラッグループは重なった後ではなく、ドラッグ閾値を超えた最初の移動から開始します。COM を入力同期フック内で呼ばないよう開始はポストし、操作ごとの番号と保留フラグで重複や古いメッセージを除外します。カーソルが表示領域へ入った時点から、同じ OLE 処理で判定します。

自動整列と等間隔整列のフラグを尊重します。標準の `LVA_SNAPTOGRID` だけでは巨大アイコンが同じセルへ集まることがあるため、指定サイズと間隔に合うグリッドへ独自にスナップします。未選択項目のセルを先に確保し、移動した項目同士の衝突も避けます。

## コンテキストメニュー

マウスによる要求は、実際の画面座標を付けた `WM_CONTEXTMENU` を既存の Shell ビューへ送り、Explorer のマウス用メニュー表示経路に委譲します。`IContextMenuSite::DoContextMenuPopup` を直接呼ぶとこの経路を通らず、Alt を押していなくても WinUI のキー案内が表示されることがあるためです。Explorer が新形式・従来形式・Shift の拡張メニュー・「その他のオプションを確認」を選びます。形式の選択をレジストリで変更しません。

キーボードから開く場合は、拡大された選択項目の表示位置を求め、既存の `IShellView::GetItemObject` と `IContextMenuSite::DoContextMenuPopup` に委譲します。`IContextMenuSite` は非推奨ですが、対象 Explorer が公開するものを利用しています。別途作ったメニューで Windows 11 の表示を模倣しません。テストホストだけは従来型メニューで検証します。

右クリック時はキャプチャを解放してから要求をポストします。新形式メニューは非同期に表示されるため、表示関数の戻りだけで成功とは判定しません。開発用検証では対象 UI スレッドのポップアップ、従来形式では `WM_ENTERMENULOOP` を観測し、テスト専用タイマーから Esc で閉じます。

従来形式のアクセスキーの下線は、メニューを開く直前に Shell ビューへ `WM_UPDATEUISTATE` を送り、`UISF_HIDEACCEL` を更新します。キーボードから開いた場合・Alt を押している場合・Windows のアクセスキー常時表示設定を尊重します。このフラグだけでは WinUI の独立したキー案内ポップアップを制御できないため、マウスの表示経路も分けています。仕様は [WM_CONTEXTMENU](https://learn.microsoft.com/en-us/windows/win32/menurc/wm-contextmenu)、[WM_UPDATEUISTATE](https://learn.microsoft.com/en-us/windows/win32/menurc/wm-updateuistate)、[SPI_GETKEYBOARDCUES](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-systemparametersinfow) を参照してください。

Explorer 向けの回帰試験は実際のマウス入力を `SendInput` で送り、背景・項目のメニューが表示されてから 600 ms 観測します。WinUI のキー案内用ポップアップを数えて非表示を確認し、メニュー全体の実表示を PNG に保存します。タスクバーや別ウィンドウを誤ってクリックしないよう、入力位置が対象 ListView 上にあることも確認します。Win32 の表示フラグだけを検査しても、この回帰は検出できません。

## 復元と所有権

標準画像リストと Shell のウィンドウは Shell が所有します。コアはそれらを破棄しません。専用画像リスト・読み込み画像・GDI+ リソースはコアが所有します。

ドロップ先の中継と元の Shell ドロップ先は UI スレッドで COM 参照を保持します。解除時に中継の OLE 登録を取り消し、置き換えていた元の登録を復元します。元の登録が親ウィンドウ側にあった場合は親の登録を維持し、追加した子の登録だけを取り消します。適用途中の失敗とウィンドウ破棄も同じ解除経路で処理します。

適用直前の画像サイズ・間隔・配置を記録し、解除時に復元します。適用中に変更した整列設定は維持し、最後に有効な整列を反映します。従って、自動整列を再有効化した場合などは位置が正規化されます。自由配置では元の位置との完全一致を検証します。

サブクラス解除後も実行中のコールバックを安全に完了させるため、Explorer 内の DLL 参照は残します。更新は解除後に別フォルダーで行います。指定時間の試用にはタイマーによる自動復元があります。

## 検証の範囲

1024 px の描画、サイズ範囲、期限付き復元、画像リストの交換／リサイズ、並べ替え後の描画・座標・期限・バックアップ、選択、Ctrl / Shift、逆方向・スクロール後の範囲選択、単体／複数移動、キャンセル、プレビューとホットスポット、整列切り替え、背景／項目／キーボードのコンテキストメニューを検証します。

現在の実機向けの回帰試験です。混在 DPI、全 Shell 拡張、全 Windows ビルドへの互換性を示すものではありません。

操作検証では、ドロップ先の強調表示を画素で比較し、アイコン下部・ラベル・スクロール後のヒットテスト、実際のドラッグ補助機能の説明表示フラグ、ドロップへの委譲とキャンセルを確認します。Explorer 向け検証では、内部矩形に対する本来のドロップ先と拡大領域に対する中継を比較し、通常／Ctrl／Shift／右ドラッグの効果・強調状態・説明文が一致することを確認します。実ファイルの移動・削除は実行しません。

`validate-interaction.ps1 -DropFeedbackOnly` はこのドロップ検証だけを 64 / 256 / 512 / 1024 px で実行し、`-Explorer` で実際の Shell ビューとの比較も行います。項目の配置を動かす操作検証は従来どおり 512 / 1024 px で実行します。

テーマ色は、Explorer テーマを設定した独立ホストと、独自描画を使わない別の標準 ListView の描画色を比較します。実際のデスクトップではそのウィンドウ固有のテーマを使用します。画像初期化後の `IsShowingText` と、`GiveFeedback` から画像ウィンドウへの更新通知の到達も確認します。

実表示を確認する場合はテストホストで F8 を押してからパッチを適用します。プレビューのドロップ先は模擬処理で、実ファイルは移動・コピー・削除しません。マウスでドロップすると画像とヒントを最大 30 秒保持し、Esc で終了します。ホスト側も通常の OLE 登録を使うため、ドラッグ閾値から画像とヒントの描画まで確認できます。

`validate-imaging.ps1` はデスクトップを変更せず、画像ワーカーと同じ MTA で実際の Shell 画像取得を検証します。横長 PNG のサムネイルと画素を比較し、解像度・縦横比・透明度・アイコンへのフォールバック・手動画像の優先を確認します。
