# 実装メモ

DekaDesktopIcon は Explorer 自身のデスクトップ ListView に DLL を読み込み、描画サイズを拡張します。実行ファイルの機械語やディスク上の Windows ファイルは変更しません。

## ソース構成

| ファイル | 責務 |
| --- | --- |
| `src/DekaDesktopIcon.cpp` | GUI、引数処理、画像設定、JSON 出力 |
| `src/CommandClient.cpp` | 対象検証、排他、DLL フック、IPC、保存済み配置の復旧 |
| `src/Protocol.h` | コマンド、共有メモリ形式、メッセージ識別子 |
| `src/Win32Support.h` | パス、設定ファイル、共通 Win32 ヘルパー |
| `src/ShellDesktop.h` | デスクトップ検出、IFolderView2、項目の識別、配置バックアップ |
| `src/DekaDesktopIconCore.cpp` | 状態管理、ListView サブクラス、描画、同期、復元 |
| `src/Imaging.h` | WIC 読み込み、Shell 画像取得、GDI+ 変換 |
| `src/Interaction.h` | 選択、範囲選択、内部移動、プレビュー、Shell ドラッグへの委譲 |
| `src/ContextMenu.h` | Explorer 標準メニューへの委譲、非同期表示の観測 |
| `tests/RegressionChecks.h` | コア内で実行する操作・整列・メニューの開発用検証 |
| `tests/DekaDesktopIconTestHost.cpp` | 独立したネイティブ ListView による試験 |
| `tests/DekaDesktopIconSortTest.cpp` | 実際の Explorer の並べ替えコマンドの試験 |

コア内部のヘッダーは同じ匿名名前空間で状態・座標変換を共有します。検証コードを別ファイルに分けていますが、実際の入力経路を検証するためコアにコンパイルします。

## 適用と通信

コントローラーは対象のプロセスパス、ログインセッション、ネイティブウィンドウ構造を検証します。対象 UI スレッドに一時的な `WH_GETMESSAGE` フックを設定して DLL を読み込みます。登録メッセージを PostMessage で送り、処理の完了を待ってフックを解除します。Shell の COM 処理は入力同期 SendMessage の中では実行しません。

共有メモリは `Local\DekaDesktopIcon-v3-<pid>`、プロトコルはバージョン 3 です。コントローラー間は名前付き mutex で直列化します。アクティブな DLL のフルパスを照合し、別フォルダーのコピーで上書きしません。改名前の v2 マッピングも読み取り専用で調べ、有効な旧パッチの上にサブクラスを重ねることを防ぎます。

ListView と親の `SHELLDLL_DefView` のサブクラス、および関連状態の変更はデスクトップ UI スレッドで実行します。画像読み込みはワーカーで行い、世代番号で古い結果を破棄します。公開された画像は mutex の下で参照を共有します。

## 描画と同期

専用画像リストに指定サイズを設定し、`NM_CUSTOMDRAW` で画像・ラベル・選択表示を描きます。手動の画像割り当てを WIC で優先して読み込み、割り当てがない項目は `IShellItemImageFactory::GetImage` に最大描画サイズの 1024 px を要求します。`SIIGBF_RESIZETOFIT | SIIGBF_BIGGERSIZEOK` により Shell のサムネイルを優先し、サムネイルがない項目は標準アイコンを取得します。取得した画像は縦横比を保って中央に拡大表示します。

Explorer が並べ替え等で画像リストを交換・縮小した場合は、最新の標準リストを復元対象として保持し、専用リストを再設定します。項目順・識別子・配置を同期し、元の配置のバックアップや試用期限を更新しません。項目の一致判定にはインデックスではなく Shell の解析名を使います。

表示上のアイコン矩形と標準 ListView の内部矩形は一致しない場合があります。矩形取得・ヒットテスト・選択・範囲選択・ドラッグを同じビュー座標で処理し、描画時にクライアント座標へ変換します。プレビューは透過画像と掴んだ位置を保持します。内部移動は Shell の項目位置 API に反映し、外部へのドラッグは標準経路へ委譲します。

自動整列と等間隔整列のフラグを尊重します。標準の `LVA_SNAPTOGRID` だけでは巨大アイコンが同じセルへ集まることがあるため、指定サイズと間隔に合うグリッドへ独自にスナップします。未選択項目のセルを先に確保し、移動した項目同士の衝突も避けます。

## コンテキストメニュー

既存の `IShellView::GetItemObject` から項目／背景のメニューを取得し、既存ビューが提供する `IContextMenuSite::DoContextMenuPopup` に表示と実行を委譲します。Explorer が新形式・従来形式・Shift の拡張メニュー・「その他のオプションを確認」を選びます。形式の選択をレジストリで変更しません。

`IContextMenuSite` は非推奨のインターフェイスですが、対象 Explorer が公開するものを利用しています。別途作ったメニューで Windows 11 の表示を模倣しません。テストホストだけは従来型メニューで検証します。

右クリック時はキャプチャを解放してから要求をポストします。新形式メニューは非同期に表示されるため、表示関数の戻りだけで成功とは判定しません。開発用検証では対象 UI スレッドのポップアップ、従来形式では `WM_ENTERMENULOOP` を観測し、テスト専用タイマーから Esc で閉じます。

## 復元と所有権

標準画像リストと Shell のウィンドウは Shell が所有します。コアはそれらを破棄しません。専用画像リスト・読み込み画像・GDI+ リソースはコアが所有します。

適用直前の画像サイズ・間隔・配置を記録し、解除時に復元します。適用中に変更した整列設定は維持し、最後に有効な整列を反映します。従って、自動整列を再有効化した場合などは位置が正規化されます。自由配置では元の位置との完全一致を検証します。

サブクラス解除後も実行中のコールバックを安全に完了させるため、Explorer 内の DLL 参照は残します。更新は解除後に別フォルダーで行います。指定時間の試用にはタイマーによる自動復元があります。

## 検証の範囲

1024 px の描画、サイズ範囲、期限付き復元、画像リストの交換／リサイズ、並べ替え後の描画・座標・期限・バックアップ、選択、Ctrl / Shift、逆方向・スクロール後の範囲選択、単体／複数移動、キャンセル、プレビューとホットスポット、整列切り替え、背景／項目／キーボードのコンテキストメニューを検証します。

現在の実機向けの回帰試験です。混在 DPI、全 Shell 拡張、全 Windows ビルドへの互換性を示すものではありません。

`validate-imaging.ps1` はデスクトップを変更せず、画像ワーカーと同じ MTA で実際の Shell 画像取得を検証します。横長 PNG のサムネイルと画素を比較し、解像度・縦横比・透明度・アイコンへのフォールバック・手動画像の優先を確認します。
